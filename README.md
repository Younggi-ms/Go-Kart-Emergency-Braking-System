Go-Kart-Emergency-Braking-System
===================================
## 프로젝트 개요

본 프로젝트는 교내 이동 수단의 안전성 문제를 해결하기 위해
초음파 센서를 이용한 장애물 인식 기반 고카트 긴급 제동 시스템을 개발하는 것을 목표로 하였습니다.

기존 자전거·킥보드는 충돌 위험이 높고, 수동 제동에 의존한다는 한계가 있었습니다.
이에 따라 주행 중 장애물 감지 시 자동으로 모터 출력을 차단하는 전자식 제동 시스템을 구현하였습니다.

## 🎯 개발 목표 (Objectives)

- 실사이즈 고카트 제작
- BLDC 모터 기반 구동계 전자화
- 초음파 센서를 이용한 1m 이내 장애물 인식
- 장애물 감지 시 즉각적인 모터 출력 0 제어
- 실제 주행 환경에서 제동 성능 검증

## 🛠️ 시스템 구성 (System Architecture)

### 하드웨어 구성
- Raspberry Pi 5 : 전체 제어 로직 처리
- 초음파 센서 : 전방 장애물 거리 측정
- BLDC 모터 + 모터 컨트롤러
- Throttle 입력 신호
- Hall Sensor (A, B, C) : 속도 및 회전 정보 피드백
- 실사이즈 고카트 프레임
### 소프트웨어 구성
- 장애물 감지 로직
- 주행 / 제동 상태 제어 FSM
- 모터 출력 제어 로직

## 본인 담당 역할 및 구현 역량

### 담당 범위
제어 소프트웨어 전체를 설계하고 구현하였습니다. (`Gokart_Breaking_System.py`)

### 주요 구현 내용
- **멀티스레드 아키텍처 설계**: `input_thread`(사용자 입력 처리)와 `distance_monitor`(100ms 주기 센서 폴링)를 독립 스레드로 분리하여 실시간 응답성 확보
- **Thread-safe 센서 접근**: `threading.Lock()`으로 두 스레드 간 초음파 센서 공유 시 발생하는 경쟁 조건(race condition) 방지
- **초음파 TOF 계산 직접 구현**: 2μs 트리거 펄스 → 10μs 유지 → 왕복 시간 측정 → `(pulse_duration × 34300) / 2` cm 변환 로직 직접 작성
- **PWM 모터 제어**: `lgpio` 라이브러리로 6kHz 주파수 PWM 출력, 0~100% 듀티 사이클 범위 검증 포함
- **FSM 상태 전환**: `obstacle_detected` 플래그 기반 주행/제동 상태 전환, 장애물 해제 시 자동 복귀 로직
- **안전한 자원 해제**: `finally` 블록으로 비정상 종료(KeyboardInterrupt) 시에도 PWM 강제 정지 및 GPIO 칩 해제 보장

### 핵심 기술 판단
- 기계식 제동 대신 전자식 제동(모터 출력 즉시 차단) 채택: 제동 반응 지연 최소화 목적
- 계산 지연 최소화를 위해 단일 거리 임계값(100cm) 조건 설계: 복잡한 판단 로직 배제

##  회로 설계 개요
- 초음파 센서 → Raspberry Pi GPIO 연결
- BLDC 모터 컨트롤러
> - Throttle 신호 입력
> - Hall Sensor 신호 입력 (속도·회전 감지)
- 제동 시 Throttle 출력 강제 0

  회로 설계는 실제 고카트 환경을 고려하여 노이즈 및 지연 최소화에 중점

## 실험 및 결과 (Results)

제동 거리 실험 결과
- 속도 증가에 따라 제동 거리 비례 증가
- 최소 안전 제동 거리: 약 2.5m

성능 분석
- 오차 발생 원인
- 노면 마찰 계수 변화
- 장애물 인식 → 제어까지의 시간 지연
- 전자식 제동의 반응 속도는 양호

### 한계점
- LiDAR 기반 장거리 인식 구현 실패
- 초음파 센서 특성상
> - 각도 민감
> - 반사체 재질 영향 존재
- Raspberry Pi 5의 전력·부피 문제

### 🚀 추후 발전 방향

- LiDAR 센서 적극 도입
- 제어 보드 경량화 (Raspberry Pi → MCU 계열)
- 다중 센서 융합 (Ultrasonic + LiDAR)
- 제동 거리 예측 기반 선제 제동 알고리즘

## 디지털 포렌식 연계 및 AI 확장 가능성

### 디지털 포렌식과의 연결

- **IoT 장치 데이터 획득**: 실시간 GPIO 센서 데이터 수집 및 스레드 안전 처리 경험 → 임베디드 장치에서 포렌식 증거 획득 시 동일한 저수준 인터페이스 활용
- **이벤트 로그 재구성**: FSM 상태 전환 기록(주행 → 감지 → 제동)은 사고 재현을 위한 이벤트 시퀀스 추적과 동일한 구조
- **차량 운행 기록(EDR) 분석**: 속도·제동 이벤트 데이터 수집 경험 → 자동차 블랙박스·EDR 데이터 포렌식 분석의 기반

### IoT 보안 취약점 관점
- 초음파 센서 신호가 암호화 없이 GPIO로 직접 입력되는 구조 → **센서 스푸핑 공격** 취약점 직접 경험
- Raspberry Pi의 무선 인터페이스(Wi-Fi/Bluetooth) 활성화 시 원격 제어 신호 위변조 가능성 → IoT 보안 분석 연구 관점

### AI 확장 가능성
- 제어 신호 시계열 데이터(PWM 출력, 거리 값, 상태 플래그)에 **이상 탐지 모델 적용** → 정상 주행 vs 사이버 공격(급발진 조작) 패턴 분류
- 다중 센서 융합 환경에서 **센서 데이터 위조 탐지** AI 모델 연구로 확장 가능
- 차량 제어 시스템 포렌식에서의 **행동 패턴 기반 이상 탐지** 연구 주제로 발전 가능
